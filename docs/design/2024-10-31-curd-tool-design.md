# CURD 代码生成工具设计

> 状态：已完成基本功能，持续迭代

## 背景

放弃直接使用 Sponge 后，决定自研 CURD 代码生成工具。从 DB 出发，通过 GormGen 生成 model，再利用 Go 反射从 model 获取表信息，生成后续代码。

## 设计目标

### 核心理念：用户提供"示例代码"作为模板

通过修改"示例代码"来控制生成代码的风格，而不是内置固定的代码模板。这回避了一系列不该做的功能（如程序初始化、MySQL/Redis 初始化等非业务代码）。

### 关键原则

1. **生成代码不可修改**：生成的代码文件（类似 `xxx.pb.go`）不应手动修改，而是在另外的文件中扩展功能。这意味着多次"生成"是幂等操作。
2. **服务自带 swagger 文档**：对外接口自动包含文档。

## 技术方案

### 生成流程

```
DB 表结构 → GormGen 生成 model → 反射获取表信息 → 生成代码
```

预留替换实现的空间，后续可以改为直接从数据库查询表结构信息。

### 代码生成链路

1. **生成 Dao 代码**：通过字符串替换（短期），后续考虑正则表达式。设计可替换的"替换逻辑"封装。
2. **生成 Proto 文件**：从 model 推导字段类型，生成 protobuf 定义，进而生成 pb 代码。
3. **生成 CURD 业务代码**：本质是 Dao ↔ Proto ↔ HTTP/gRPC 之间"左手递右手"的转换代码。

## 已实现

- 从 MySQL 表结构生成 GORM model、Proto 定义、gRPC/HTTP 桩代码
- Service 业务层 + Data 数据层基础 CRUD 代码
- 服务入口 main 文件（基于 abandonCode 模板替换生成）
- `make gorm` + `make curd` 一键生成
