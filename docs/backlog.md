### 76. Grafana 两个面板无数据排查

- **状态**：Done，2026-10-10 用户确认部署验收通过。
- **专题**：[登录性能专题中枢](design/2026-09-30-01-login-performance-hub.md)。
- **背景**：用户反馈 Dependency status 和 Average connection wait 无数据。
- **分析**：2026-10-10 通过部署环境 Prometheus 公共查询 API 核对，应用抓取状态为 1，依赖状态序列为空。修改前依赖状态只在访问健康检查端点时创建和更新，指标抓取不执行检查。数据库累计等待次数已有 89650，最近一分钟等待次数和等待时长的瞬时速率均为 0；平均连接等待查询过滤零等待时段，当前空白符合已有口径，不是等待指标漏采。
- **方案**：诊断服务启动后立即异步检查，之后每 15 秒刷新。定时任务与健康接口复用底层检查及已有依赖状态指标，健康接口仍执行实时检查，指标端点只读取最近检查结果。沿用两秒检查超时；停止服务时取消并等待定时任务退出。平均连接等待保持无等待时无有效均值的语义。
- **任务**：

  - [x] 用户确认异步定时检查方案。
  - [x] 提取共用检查逻辑并接入诊断服务生命周期。
  - [x] 验证首次刷新、周期刷新、实时检查、慢检查不阻塞指标及停止取消。
  - [x] 同步面板说明和观测文档。
- **验收**：
  - [x] 明确区分依赖状态未刷新和零等待时段无有效均值。
  - [x] 自动测试验证周期检查及实时检查共用指标，可达与不可达状态正确。
  - [x] 部署环境 Dependency status 显示已初始化依赖状态，2026-10-10 用户确认。
- **AI 自动验证**：`go test -race ./pkg/papp -count=1`、`make build`、dashboard JSON 解析与 `git diff --check` 均通过；覆盖首次/周期刷新、正常/异常状态、未启用依赖、健康接口实时检查、慢检查不阻塞指标和停止取消。原有指标测试补齐自身数据准备，消除测试顺序依赖。测试进程已结束，无遗留服务。

### 77. 合并展示状态历史

- **状态**：Done，2026-10-10 用户确认紧凑时间线及关闭分页验收通过。
- **专题**：[登录性能专题中枢](design/2026-09-30-01-login-performance-hub.md)。
- **背景**：用户希望把现有状态放进同一个历史图，查看某个组件是否曾经掉线。
- **分析**：现有两个状态面板为即时查询，只呈现当前状态。历史展示需范围查询，保留实例与依赖名称；抓取状态表示指标端点可达，依赖状态表示最近一次检查结果，两者需要独立标识。缺失数据不能填成健康，周期检查和抓取之间发生的短暂掉线可能未被记录。
- **方案**：把两个即时状态面板合并为全宽状态时间线，使用两条历史范围查询，分别展示指标抓取与各依赖。保留原五格面板高度，关闭分页、全部状态同页展示，色带收窄至单行文本量级，隐藏色带内重复状态文字与底部图例；左侧标识组件，悬停查看状态及持续时间。连续相同状态合并，缺失值不连接、不填充为健康。同步观测文档与专题中枢。
- **任务**：
  - [x] 确认当前状态面板配置及历史展示目标。
  - [x] 用户选择紧凑状态时间线，并明确关闭分页，由用户控制状态数量。
  - [x] 调整面板、查询与文档，验证状态映射、缺失值配置及线上历史查询。
- **验收**：
  - [x] 同一面板使用两条范围查询，分别返回指标抓取与各依赖历史状态。
  - [x] 配置绿色正常、红色异常映射，缺失值不连接且不填充。
  - [x] 部署后确认时间线色带与单行文本高度接近，状态历史可读，关闭分页展示全部状态，2026-10-10 用户确认。
- **AI 自动验证**：关闭分页后，JSON 解析与配置检查确认分页数为零、所有状态同页展示；部署配置回归测试通过；配置脚本确认合并面板、五格高度、范围查询、状态映射、空值处理与面板编号唯一。部署环境 Prometheus 最近五分钟范围查询成功返回 metrics scrape、database、rabbitmq 三条序列，各 21 个采样点。JSON 解析与 `git diff --check` 通过；测试进程已结束，无遗留服务。
