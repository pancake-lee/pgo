### 45. 精简 profile 与业务状态挂钩

- **状态**：Done
- **背景**：CPU profile 请求被额外互斥锁串行化，业务状态指标没有调用方，runtime profile 脚本需要开窗和下载两步。
- **方案**：去掉 CPU 排队包装并直接挂载标准 pprof handler，删除无调用方的业务状态 API、指标及面板，同步数据映射。runtime 采用用户选择的 A：一次 POST 指定单个 profile 和采集秒数，通过标准 pprof 增量 handler 等待后返回二进制结果；删除旧开窗状态与 gated GET 路由，CLI 改为一次请求。
- **分析**：标准库 CPU profiler 同时只允许一个采集，重叠请求直接失败，不能解释为并行 CPU 采集。runtime 已合并为单次 POST 采集并返回增量 profile，CLI 同步使用一次请求。goroutine 增量表示区间栈分布变化，不是末时完整堆栈快照。
- **任务**：
  - [x] 移除 CPU 排队包装与无调用业务状态挂钩。
  - [x] 用户选择 runtime profile 交互并完成对应实现。
  - [x] 同步仪表盘、文档与相关诊断回归，收尾集中验证。
- **验收**：
  - [x] CPU profile 重叠请求不会在应用锁上排队。
  - [x] 当前代码和仪表盘不再暴露未使用的业务状态。
  - [x] runtime 接口及 CLI 行为符合用户选择，相关回归通过。
