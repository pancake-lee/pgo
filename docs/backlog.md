### 14. genCURD Proto 表归属映射

- **状态**：Done
- **背景**：`inferServiceName` 在 `cmd/pgo/tools/genCURD/genCURD_core.go` 内硬编码 `task`、`course` 等前缀和 `default` 回退；调用方无法覆盖规则。
- **方案**：以服务 Proto 的 PGO 自定义 option 作为表到服务的唯一映射来源，不引入独立配置或命令行交互。生成前读取全部 Proto 中的已映射表，未映射表统一登记到生成器维护的 `z_defaultService.gen.proto`，并生成 default service 的 CRUD 代码。用户将映射声明从 default Proto 剪切到自定义服务 Proto 后重新生成，代码随映射迁移；生成器在默认 Proto 的映射区和控制台同时提示待归属表与迁移方式。详见 [Proto 表归属映射](design/2026-09-07-proto-table-mapping.md)。
- **任务列表**：
  - 定义并随工具提供 Proto 表归属 option，解析全部服务 Proto 的映射并校验重复、未知表与非法服务声明。
  - 生成和维护 default service Proto 的映射区、简短迁移注释及对应 CRUD 代码，确保 SQL 起步可直接生成。
  - 按 Proto 映射替代服务名猜测，输出服务到表的生成摘要和 default service 待归属提示。
  - 建立 SQL 起步、映射迁移、未映射表、重复映射和未知表的离线 fixture 回归。
- **验收**：仅提供 SQL 时生成包含全部表的 default service；用户剪切映射到自定义 Proto 后 CRUD 代码迁移到该服务；default service 与控制台均准确显示未映射表；冲突映射在写文件前失败。
- **实施与验证**：新增 `pgo.tables` 服务 option 和 Proto 映射解析。未映射表生成到 default service，并在 default Proto 写入迁移说明和映射；生成日志输出各服务表集合与待迁移表。定向映射测试、Proto 编译和离线全仓质量检查通过。

### 16. genCURD 支持多主键表

- **状态**：已规划
- **背景**：`newTable` 检测到多个主键后将 `PriCol` 置空；DAO、Proto、Service 模板据此移除主键相关的 Update/Delete 逻辑。
- **方案**：将生成器的单一 `PriCol` 模型扩展为有序主键列集合；Update/Delete 请求、服务转换和 DAO 条件都包含全部主键，并只以完整主键组合作为定位条件。保留无主键表的只读生成行为，并以 SQLite 和 MySQL 的联合主键样例回归。
- **任务列表**：
  - 重构表元数据和模板替换逻辑，使其接受主键列集合。
  - 更新 Proto、Service、DAO 生成结果和零值/类型校验。
  - 建立单主键、联合主键、无主键三组 fixture，并验证生成代码可编译及 SQL 条件完整。
- **验收**：联合主键表生成完整 Update/Delete；SQL 条件包含且仅包含全部主键；单主键和无主键行为不回归。

### 17. 全量测试与静态检查不可通过

- **状态**：Done
- **背景**：2026-09-07 仓库评估中，`GOTOOLCHAIN=local go test ./...` 失败；`pkg/papp.TestJwt` 稳定返回 `auth failed`，`pkg/plogger/warper.go:37` 被 `go vet` 判定为非固定格式串。全量测试不能作为提交前质量门槛。
- **严重程度**：高。
- **评估**：5.6，见 [2026-09-07-repository](../../eval/reports/2026-09-07-repository.md)。
- **分析**：JWT 失败是测试构造的认证上下文与生产读取契约不一致；日志包装器则把普通错误文本当作格式串，导致静态检查拒绝该调用。两者均为确定性代码/测试错误，不依赖真实环境。
- **方案**：令 JWT 测试通过与认证中间件一致的上下文契约覆盖取值路径；将日志包装器的纯文本错误与格式化错误分开构造，保留原有错误文本语义并消除动态格式串。任务 18 完成后，以默认离线测试集作为本任务的全量回归入口。
- **任务列表**：
  - 对照认证上下文的写入与读取约定，修正 `papp` JWT 测试的上下文构造，并补充认证失败的边界断言。
  - 修正 `plogger` 纯文本错误的构造方式，保留带参数格式化 API，并为两种输入增加单元测试。
  - 运行离线全量测试和 `go vet ./...`，记录失败包或通过结果。
- **验收**：默认离线 `GOTOOLCHAIN=local go test ./...` 通过；`GOTOOLCHAIN=local go vet ./...` 无动态格式串诊断；JWT 成功与无效认证上下文均有稳定断言。
- **实施与验证**：JWT 测试改为使用认证中间件写入的 claims 上下文键，并覆盖缺失 claims；纯文本日志错误改用 `errors.New`，格式化入口保持不变。离线全量测试和 `go vet ./...` 均通过。

### 18. 外部依赖测试未隔离，干净环境 panic

- **状态**：Done
- **背景**：2026-09-07 仓库评估中，`papitable`、`predis`、`pweixin` 与用户服务测试依赖未提交的 `.local/my-config.yaml`、外部服务或已初始化数据库；缺失时由 `MustInitConfig` 或 nil GORM DB 触发 panic。执行 `go test ./...` 时无法区分离线单元测试与环境集成测试。
- **严重程度**：高。
- **评估**：5.6，见 [2026-09-07-repository](../../eval/reports/2026-09-07-repository.md)。
- **分析**：现有测试把网络、凭据和已初始化数据库当作默认前提，既不能在干净工作区运行，也无法向维护者说明何时需要真实环境。当前优先恢复可重复的离线门禁，不在本任务中扩大为客户端架构重构。
- **方案**：按测试前提将真实 APITable、Redis、企业微信和用户数据库用例划为 `integration` 测试标签；默认测试只收录不读取本地密钥、不连接服务的离线测试。为集成测试提供显式 Make 入口，启动前集中校验配置文件、必要配置项和连接前提，缺失时返回可行动的错误而非 panic；不提交任何真实凭据。
- **任务列表**：
  - 盘点依赖配置、网络或真实数据库的现有测试，并迁移至集成测试标签。
  - 为默认离线测试和显式集成测试分别提供稳定入口；集成入口说明配置位置与所需服务，不自动启动或销毁外部资源。
  - 将集成测试的前置检查改为清晰失败信息，消除未初始化配置或数据库导致的 panic。
  - 在无本地配置的干净工作区验证默认测试；在具备条件的本地环境验证集成入口可发现并执行对应测试。
- **验收**：没有 `.local/my-config.yaml`、Redis、第三方凭据或业务数据库时，默认 `GOTOOLCHAIN=local go test ./...` 不 panic；真实依赖测试仅由显式集成入口执行；前置条件缺失时错误明确说明缺少的配置或服务。
- **实施与验证**：真实服务测试已标记为 `integration`，默认离线测试通过。`make test-integration` 在缺少配置时明确提示所需配置与服务，带标签的配置读取也改为测试失败而非 panic。

### 19. genCURD 失败可能删除既有生成产物

- **状态**：Done
- **背景**：2026-09-07 仓库评估发现，`runGenerate` 在初始化数据库、读取表结构及校验后续生成条件前执行 `rmAllGenFile`。当数据库连接、表读取或后续生成失败时，既有 `*.gen.go` / `*.gen.proto` 可能已被删除，违反 PRD 的“生成失败不得留下半成品或写入意外目录”质量要求。
- **严重程度**：高。
- **评估**：5.6，见 [2026-09-07-repository](../../eval/reports/2026-09-07-repository.md)。
- **分析**：删除动作早于数据库与模板生成的可失败步骤，且后续多个写入阶段没有统一回滚边界；只把删除延后仍无法处理生成中途失败。
- **方案**：把 genCURD 的输出发布改为事务式流程：先完成数据库、表结构、模板等前置校验，再在受控的生成会话中保留既有生成产物快照；只有全部代码生成和 API 生成成功才发布新结果并清理过期产物，任一阶段出错则还原快照并清理本轮临时内容。限制清理范围为生成器清单覆盖的目标目录，保持现有成功生成结果的目录与命名兼容。
- **任务列表**：
  - 重排生成前置校验，保证数据库连接、表读取和模板表解析完成前不触碰既有产物。
  - 建立生成会话的快照、提交和回滚边界，覆盖 DAO、Proto、API、Service 与入口接线的生成文件。
  - 为数据库连接失败、表解析失败和生成中途失败建立回归用例，逐一比对失败前后的产物；补充成功路径的过期生成文件清理断言。
- **验收**：任一生成阶段失败后，已有生成文件内容与文件集合保持不变，且不遗留临时或半成品文件；成功生成后产物可编译并清理对应的过期生成文件；不会删除非生成文件或意外目录内容。
- **实施与验证**：生成会话在数据库和模板前置校验完成后创建快照，失败时恢复 DAO、Proto、API 和 OpenAPI 产物，成功时才清理过期生成文件。回归用例覆盖回滚新增/修改产物及成功清理过期产物。

### 20. build 构建元数据为空

- **状态**：Done
- **背景**：2026-09-07 执行 `make build` 时，实际命令为 `-X main.commit= -X main.date=`。`Makefile` 的 `build` 目标将 `git rev-parse HEAD` 和 `date` 写为 Make 变量形式，导致提交号和构建时间未写入二进制。
- **严重程度**：中。
- **评估**：5.6，见 [2026-09-07-repository](../../eval/reports/2026-09-07-repository.md)。
- **分析**：`build` 目标将 shell 命令误写成 Make 变量引用；它与 `cli`/`cli-win` 的元数据注入方式不一致，因而构建可成功但产物不可追溯。
- **方案**：统一各构建目标的提交号与构建时间求值方式，使 Make 在调用 Go 编译前取得当前仓库提交和时间；保留现有版本参数与 `bin/` 输出边界。为非 Git 工作区或提交信息不可用的情形定义显式、可识别的占位值，避免再次静默写入空字符串。
- **任务列表**：
  - 统一 `build`、`cli` 和 `cli-win` 的构建元数据参数来源与求值时机。
  - 在当前 Git 工作区构建并检查二进制实际包含非空提交号和构建时间。
  - 验证元数据获取失败时的构建输出可识别，不伪装为正常的空值。
- **验收**：`make build` 生成的每个适用二进制包含非空、可追溯的版本、提交号和构建时间；CLI 构建目标的元数据格式保持一致；元数据来源不可用时输出明确占位值或失败原因。
- **实施与验证**：构建目标统一注入版本、完整提交号和 UTC 时间，Git 信息缺失时使用 `unknown`。`make cli` 后的 `./bin/pgo --version` 已输出三项非空元数据。

### 21. P0 生成链路缺少自动化回归与 CI 证据

- **状态**：Done
- **背景**：2026-09-07 仓库评估发现，`genCURD`、`genGORM`、`sheet2mysql` 及多数服务包没有测试文件，未发现 CI 配置。`make gorm` 会删除数据库与生成目录，评估无法以无副作用方式验证 P0 生成链路；当前也没有持续验证记录证明生成结果可编译且兼容。
- **严重程度**：中。
- **评估**：5.6，见 [2026-09-07-repository](../../eval/reports/2026-09-07-repository.md)。
- **分析**：生成器的验证依赖会改写共享数据库和工作目录的正式 Make 目标，无法用作回归测试；同时缺少持续执行的事实来源。任务 17、18、19 是建立稳定默认门禁和无副作用生成测试的前置依赖。
- **方案**：在临时工作区和受控 fixture 中为 P0 生成链路建立无副作用回归：覆盖输入校验、代表性生成结果和生成结果编译，不调用会删除共享数据库或现有产物的正式目标。将离线测试、静态检查、构建及生成器 fixture 回归汇成单一验证入口，并由 CI 在变更时执行；真实外部集成测试继续沿用任务 18 的显式入口，不放入默认 CI。
- **任务列表**：
  - 定义隔离的数据库/schema 与项目输出 fixture，先覆盖 genCURD 的基础生成路径，并为后续服务名映射、联合主键任务复用。
  - 为 genGORM 和 sheet2mysql 补充不修改仓库共享资源的核心输入/输出回归用例。
  - 增加统一离线质量检查入口，串联任务 17、18 的默认测试、静态检查、构建和生成器 fixture 编译。
  - 配置 CI 执行该入口并保留可定位失败阶段的日志；不注入第三方密钥或执行集成标签测试。
- **验收**：干净工作区可在不启动外部服务、不删除数据库或现有生成目录的条件下完成 P0 回归；CI 对每次变更产出测试、静态检查、构建和 fixture 编译结果；生成器关键失败与成功路径至少各有一个自动化用例。
- **实施与验证**：已为 genCURD 会话、genGORM 输入校验和 sheet2mysql DDL 添加离线回归；`make test` 串联默认测试与静态检查，GitHub Actions 在 push 和 pull request 执行该入口及构建。
